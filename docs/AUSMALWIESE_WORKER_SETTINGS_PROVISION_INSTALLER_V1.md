It demands exact main SHA, verified `main` branch, clean checkout, trusted GitHub origin, and exact Git-tracked bytes of the fixed credential-helper source. It parses that source with `ast` **without executing it**, and checks the entrypoint path, Worker, account fingerprint, installed GET release identity, local protected credential destination and fixed confirmation marker.

The read-only preflight checks `sudo -n` access to a bounded `/usr/bin/cp` capability and **version-specific exact copy arguments**, along with root-owned, non-writable parent directories, and absence of the target including dangling symlinks. **Issue #1016 adds a source-reviewed compatibility branch only for GNU coreutils cp 9.1. Versions 9.0, 9.2, 9.3, 9.4 and 9.5 fail closed.** On 2026-10-14 a read-only RPi5 query showed `cp (GNU coreutils) 9.1` and the helper not installed. ### Why not `install -m 0500`?

The ordinary `install` executable can replace a target created between a prior absence check and the write. That violates the issue's no-overwrite rule. See GNU [install invocation](https://www.gnu.org/software/coreutils/manual/html_node/install-invocation.html) and [cp invocation](https://www.gnu.org/software/coreutils/manual/html_node/cp-invocation.html).

For the **future separately authorized one-shot** `--apply` operation:

1. Complete preflight and capture the **Git-tracked** source bytes in unprivileged memory. Create an *anonymous* Linux `memfd` (no disk staging); write only those source bytes, set its mode `0500` and seal it against modification/growth/shrink.
2. Recheck exact checkout, trusted parent metadata, target absence and the **exact** `sudo -n -l --` command gate, then dispatch exactly **one** root operation using the sealed memfd as stdin. With GNU `cp 9.1`, the fixed command is `sudo -n /usr/bin/cp --no-clobber --verbose --preserve=mode -T -- /dev/stdin /usr/local/sbin/rpi5-ausmalwiese-worker-settings-provision`. With GNU `cp >=9.6`, the fixed command is `sudo -n /usr/bin/cp --update=none-fail --preserve=mode -T -- /dev/stdin /usr/local/sbin/rpi5-ausmalwiese-worker-settings-provision`. The invocation environment is fixed (`LC_ALL=C`) and **excludes `POSIXLY_CORRECT`**, which could enable the dangerous dangling-symlink fallback. A sudoers policy that injects `POSIXLY_CORRECT` would invalidate this safety argument and must be rejected at future host preflight.
3. **GNU 9.1-specific proof (source code, not a command-line assumption):** [Debian coreutils 9.1-1 `copy.c`, new destination path](https://sources.debian.org/src/coreutils/9.1-1/src/copy.c/) has `openat(..., O_CREAT | O_EXCL, ...)`; [existing target early-return](https://sources.debian.org/src/coreutils/9.1-1/src/copy.c/) silently skips under `I_ALWAYS_NO`, yielding **exit status 0**; [`emit_verbose` placement](https://sources.debian.org/src/coreutils/9.1-1/src/copy.c/) is **after** that early-return yet **before** the `O_EXCL` open. Therefore `cp 9.1 -n` **alone is not sufficient**, and `-v` alone is not a creation certificate. The installer must require **both** `returncode == 0` and **exact single C-locale stdout** `'/dev/stdin' -> 'TARGET'\n`; on a pre-existing destination, output is missing even though status is 0; on an `O_EXCL` race after the verbose line, status is nonzero. Any other output/status is STOP. This signal is checked **before** metadata/hash verification. Source hardlinks cannot enter the destination as hardlinks: this is a regular-byte copy from a sealed anonymous memfd. Any existing regular file, hardlink, symlink, or dangling symlink is rejected at absence preflight and at no-clobber/exclusive-creation boundaries. No source/destination identity alias is possible between the anonymous source memfd and the fixed on-disk target.
   `--preserve=mode` copies the sealed memfd's `0500` mode; the root-owned `cp` process creates the resulting root-owned regular file. Root executes only the fixed coreutils command: **no repository Python, generic shell, overwrite, separate root `chmod`/`chown`, temporary disk staging, alternate target or cleanup**. The one command includes its own internal file and metadata operations. Later root-owned `stat`/`sha256sum` are read-only.
4. After dispatch, verify only the installed **helper source** file's exact `root:root 0500`, regular-file/single-link metadata and SHA-256. No GET release or protected credentials are touched. Any return error, timeout, uncertain dispatch or failed post-verification is **STOP**, with no retry/rollback/cleanup. The file may be partially created on error, so it must never be overwritten.

**Source-backed reference:** GNU coreutils [9.1-1 copy.c](https://sources.debian.org/src/coreutils/9.1-1/src/copy.c/), specifically the `I_ALWAYS_NO` early return, the `emit_verbose` call preceding `copy_reg`, and the `openat(..., O_EXCL)` / `open_dangling_dest_symlink` branch; [GNU release notes](https://github.com/coreutils/coreutils/blob/master/NEWS) show `--update=none-fail` as a 9.5 feature, record the 9.6 fix for 9.5 rejecting it, and describe the non-clobber exit-status differences. Exact upstream version and downstream patches must be checked during real host preflight; the source evidence does not assert this device's binary was built from identical sources.
