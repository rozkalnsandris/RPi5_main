# Security Policy

## Supported versions

Security fixes are maintained for the current `main` branch. Older commits, branches, tags, or releases are not considered supported unless explicitly documented otherwise.

## Reporting a vulnerability

Please do **not** open a public issue for a security vulnerability.

Use GitHub's private vulnerability reporting flow:

- open the repository's **Security** page;
- choose **Report a vulnerability**;
- provide a concise description, affected component or path, reproduction steps, expected impact, and any relevant evidence.

Do not include passwords, tokens, credentials, private keys, cookies, production data, database contents, or other secrets in reports or attachments.

## Scope

This policy covers security issues in this repository's public source, workflows, automation, policy, and documented control interfaces.

Repository source can describe intended configuration and behavior, but it does not by itself prove the state of any live Raspberry Pi host, service, container, credential, permission, network, or deployed revision.

## Disclosure

Please allow time for the issue to be reviewed and addressed before public disclosure. Security fixes may be coordinated through a private GitHub Security Advisory when appropriate.
